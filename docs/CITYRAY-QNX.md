# GeePlay: приборка QNX

Новый путь экспериментальный и не требует разрешения `adnaviservice`. Он использует
отдельные QNX Screen окна: карта — TCP 53281, стрелки — TCP 53283. Порты AtlasDim
50210–50212 не используются. Реальная совместимость с Cityray ещё не подтверждена.

## Настройка

1. Откройте **Расширенные → Размещение на приборке QNX**.
2. Укажите адрес QNX, доступный с головного устройства. Пароль root вводится здесь
   только для текущего подключения, не сохраняется и не попадает в журнал.
3. Включите карту, стрелки либо оба окна. Перетаскивайте прямоугольники на схеме
   1920 × 532; поля X, Y, ширины и высоты позволяют точно изменить размещение.
   Оставьте видимыми показания автомобиля и контрольные лампы.
4. Укажите установленный демон AtlasDim для **нужного дисплея QNX**. Если поле
   пустое, GeePlay найдёт файлы `/tmp/ghudbridgelited-dim-*` и предложит выбор.
   Выбирайте тот же дисплей, на котором уже работает ваш виджет AtlasDim.
5. Нажмите **Запустить окна GeePlay и сохранить**. Создаются отдельные копии
   `/tmp/geeplay-navd-53281` и `/tmp/geeplay-navd-53283`; оригиналы не изменяются.
6. Переподключите CarPlay через появившуюся панель настроек. Включите маршрут
   в приложении iPhone, которое предоставляет CarPlay navigation UI stream.

В APK нет бинарника AtlasDim/ANHUD. Используется установленный на машине экземпляр;
условия MIT AtlasDim не распространяются на его компоненты, происходящие из ANHUD.
GeePlay не патчит дисплей установленного демона: выбранный файл уже должен подходить
для нужного дисплея.

## Поведение и диагностика

Карта берётся из дополнительного CarPlay stream 111 и масштабируется в размер окна.
Вывод ограничен пятью кадрами в секунду; очередь хранит только последний кадр.
Поток не заменяется захватом главного экрана. Если iPhone не передаёт navigation UI,
диагностика показывает `geelyQnx map=waiting_for_video`.

Стрелки используют структурированные RouteGuidance-манёвры. При отсутствии маршрута
будет `turns=waiting_for_route`; неизвестный/составной манёвр не заменяется выдуманной
стрелкой. Существующий OEM-драйвер и новый QNX-вывод диагностируются отдельно.

После потери TCP клиент повторяет подключение с задержкой. После перезагрузки QNX
каталог `/tmp` очищается: дождитесь запуска AtlasDim и повторите запуск окон GeePlay.
Постоянный root-пароль и изменения загрузочных файлов QNX не требуются.

Кнопка **Остановить окна GeePlay** проверяет полный путь процесса и порт перед
остановкой. Процессы AtlasDim не останавливаются. Изменения размещения применяются
после переподключения CarPlay; самопроизвольного разрыва сеанса нет.

## Музыка через GMediaProxy

В разделе звука включите **Медиапрокси (экспериментально)** и переподключите CarPlay.
GeePlay публикует название, исполнителя, обложку и состояние воспроизведения через
Android MediaSession даже при внешнем владельце звука. Этот режим не запрашивает
аудиофокус. Для доставки в OEM-панель требуется отдельно установленный
[GMediaProxy](https://github.com/Salat39/GMediaProxy) с предоставленным ему доступом
к уведомлениям/медиасеансам. Прокси может переключить автомобиль на источник ONLINE;
проверьте выбранного владельца музыки в настройках звука GeePlay.

## Проверки

Проверяются gcp/1 framing, CRC, границы окон, RLE32, RGBA stride/масштабирование,
обмен с локальным TCP-сервером, Telnet login/коды завершения, удаление пароля из
временного массива, изоляция процессов и невозможность остановить процесс AtlasDim.
Скриншоты редактора с увеличенным шрифтом создаются в
`vehicle-geely/build/reports/qnx-ui/` для компактной, полной и RTL-компоновки.
Эти проверки не являются подтверждением отображения на реальной приборке.
