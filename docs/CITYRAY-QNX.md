# GeePlay: независимые окна приборки QNX

Экспериментальный путь создаёт отдельные QNX Screen окна: карта — TCP **53281**,
стрелки — TCP **53283**. Устанавливать AtlasDim не требуется. Порты и процессы
AtlasDim не используются и не останавливаются. Совместимость с физической приборкой
Cityray ещё не подтверждена.

## Карта и стрелки добавляются отдельно

1. Откройте **Расширенные → Размещение на приборке QNX**.
2. Укажите адрес QNX и пароль root. Пароль не сохраняется. Пока редактор открыт,
   используется одно авторизованное подключение без повторного ввода пароля.
3. Включите флажок **Карта**, чтобы видеть её прямоугольник в предпросмотре.
   Укажите её дисплей QNX (1–5), слой (0–8), положение и размер. Нумерация QNX
   не равна Android displayId. Дисплей 2 выбран исходной настройкой, а не
   подтверждённым профилем вашей прошивки.
4. Нажмите **Добавить карту**: GeePlay устанавливает компонент и запускает только
   процесс карты. Стрелки при этом не устанавливаются и не перезапускаются.
5. Для стрелок используйте собственные поля и **Добавить стрелки**. Их дисплей,
   слой, положение и размер независимы от карты.
6. **Убрать карту** и **Убрать стрелки** останавливают только выбранный процесс
   и отключают только выбранный тип вывода. Второе окно сохраняет настройки.
7. Переподключите CarPlay через появившуюся панель настроек. При изменении
   только положения/размера достаточно сохранить размещение и переподключиться.
   Для изменения дисплея или слоя повторите добавление соответствующего окна.

Прямоугольники можно перетаскивать; размеры задаются численно. Окна должны
помещаться в 1920 × 532 и оставлять видимыми показания автомобиля и контрольные лампы.
После перезагрузки QNX каталог `/tmp` очищается: повторите добавление нужных окон.
Загрузочные файлы автомобиля не изменяются; root-пароль не хранится.

## Встроенный компонент

В APK находится `assets/qnx/geeplay-navd` — исходный бинарник из AtlasDim,
происходящий из ANHUD. Его происхождение, upstream commit и SHA-256 сохранены
в `assets/qnx/NOTICE.txt`. GeePlay не приписывает ему лицензию MIT AtlasDim.

Перед установкой проверяется SHA-256; для выбранного дисплея меняются только две
проверенные AArch64-инструкции. Передача идёт из APK напрямую в QNX короткими
пакетами команд Telnet, с проверкой контрольной суммы на QNX. Устанавливаются
`/tmp/geeplay-navd-53281` и `/tmp/geeplay-navd-53283`. Установка выбранного окна
не обращается к файлам другого окна и к файлам AtlasDim.

## Видео, манёвры и диагностика

Карта берётся из CarPlay stream 111 через стандартный
[SurfaceTexture](https://developer.android.com/reference/android/graphics/SurfaceTexture).
OpenGL сохраняет пропорции карты при масштабировании; считывание RGBA ограничено
пятью кадрами в секунду. Сеть хранит только последний кадр и использует RLE32.
При ошибке GPU основной сеанс CarPlay продолжает работу.

`geelyQnx map=waiting_for_video` означает отсутствие видеокадров от iPhone;
`connected:frames=…` показывает фактическую отправку. Стрелки получают структурированные
RouteGuidance-манёвры; `turns=waiting_for_route` означает ожидание маршрута.
Неизвестные составные манёвры не заменяются выдуманной стрелкой.

После потери TCP клиент повторяет подключение. OEM-драйвер и QNX диагностируются
отдельно. Ошибки установки показывают этап операции и причину без пароля.

## Музыка

В звуке включите **Медиапрокси (экспериментально)** и переподключите CarPlay.
GeePlay публикует метаданные через Android MediaSession даже при внешнем владельце
звука. При таком владельце аудиофокус не запрашивается. Для доставки в OEM-панель
нужен отдельно установленный [GMediaProxy](https://github.com/Salat39/GMediaProxy)
с доступом к уведомлениям/медиасеансам. Прокси может переключить источник на ONLINE.

## Локальные проверки

Тестируются gcp/1, CRC, геометрия, RLE32, порядок строк RGBA, обмен с TCP-сервером,
Telnet login/коды завершения, очистка временного пароля, побайтовая передача компонента,
проверка его контрольной суммы, изоляция процессов и независимое сохранение окон.
Скриншоты редактора с увеличенным шрифтом находятся в
`vehicle-geely/build/reports/qnx-ui/` (компактная, полная и RTL-компоновка).
Эти проверки не подтверждают вывод на реальной приборке.
